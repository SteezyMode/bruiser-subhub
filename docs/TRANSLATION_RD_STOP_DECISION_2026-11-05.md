# Translation R&D stop decision and evidence audit — 2026-11-05

**STATUS: quality-development freeze.** This document controls future subtitle research proposals. It is based on **real run reports, the GitHub code and log/benchmark history, private owner-provided bilingual audits, and the vendor documentation as of Nov 5, 2026**. No workers, model installations, subtitles or database state are modified by this record.

## Explicit decision

**STOP trying to force a consistent ~8/10 unattended English→Japanese movie/TV localization result from the existing small local Gemma/Hy/CAT/Google/Index pipeline by changing prompts, one-vs-two previous-cue histories, generation parameters, quantization tags, grouped output formats, retry logic or superficial HTML cleanup.**

This is an engineering/product stop rule, NOT a theorem that free/local translation is impossible. The existing system can quickly produce structurally complete and often intelligible Japanese drafts; it has **NOT** demonstrated consistently accurate, natural, pleasant 8/10 unreviewed Japanese. Grammatical Japanese, 100% cue coverage, GPU residency, low chars/sec and green CI are not linguistic-quality measures.

Keep the existing tuned **17slever17 Translate Gemma 4 Sub E4B** (Ollama tag `hf.co/17slever17/translate-gemma-4-sub-e4b-GGUF:Q4_K_XL`, digest prefix `9ccfc3b07081`) as the **installed OPERATIONAL FALLBACK**, not a scientifically selected *best Japanese translator*. Its documented prompt/parameters are pinned; leave them alone absent a new, successful, matched test. No new automatic library-wide translation rollout.

## Why the previous decision process was unreliable

1. **Metric substitution:** cue completeness, Japanese-script heuristics and char density were mistaken for accuracy, register, plot comprehension, and actual enjoyment. Assistant editorial scores are useful diagnostics but not native-viewer grades.
2. **Selection contamination:** Benchmarks 001–005 reused familiar, deliberately difficult *Primate* cues. Assistant-selected prompt changes overfit already-known examples. Even the 26-vs-15 E4B–HY exploratory preference could not select a language-quality winner; Bench 006 explicitly superseded it for that purpose.
3. **Fault category confusion:** v009's copied-future-dialogue is a removable **pipeline fault**; v011's misread idioms, polysemy and references persist even when structural checks pass. Prompt-length/provenance hardening and 100% GPU residency do not solve the latter.
4. **Benchmark-to-production and docs divergence:** production used generic Gemma after a tuned-model benchmark. The November 4 remediation correctly pins tuned E4B and model-native interface, but the "approved best" docs outran the independent quality evidence. Maintain one decision log and distinguish **installed fallback** from **proven winning model**.
5. **Misleading historical target:** earlier FROM and Yellowjackets subtitling had review/polish and used a different, insufficiently documented generation workflow. Comparing an unreviewed local draft to a polished editorial result is not apples to apples.
6. **Scale-first behavior:** translating whole movies and multiple American Dad episodes created large artifacts and repeated errors before closing the existing independent quality gate.

## Closed proposals — future assistants must NOT suggest again without materially new evidence

- E4B prompt variants: neutral/friendly/adult-horror slogans, profanity preservation tweaks, style labels, speaker assumptions, longer/shorter lookbacks, 1 vs 2+ previous pairs, 8-second gating.
- Generic Gemma batch JSON, numbered lines, multi-cue per-call translation and punctuational re-splitting, extra retries to salvage malformed grouped output, speculative full-utterance Japanese-as-context, or more v014/v015/v016 loops.
- Changing quantization because tag Q4_K_XL shows Q4_K_M in Ollama, switching E4B to Q8 on 6GB, changing `num_ctx`/`num_predict` for its own sake, claiming power cap changes translation meaning.
- Always-on HY backtranslation/second-model critic, majority voting/selection or translation-by-consensus without independent net benefit.
- HTML tag cleanup as a model-quality solution (mechanical hygiene is fine, but not an 8/10 upgrade).
- Claiming official CAT 3.3B, CAT 7B, Index-Translate 2B, tuned E2B, Google TranslateGemma 4B/12B or HY7 are **untried**; they have all generated real 006 outputs. HY1.8 was blocked by runtime compatibility, **not linguistically disproven**.
- Buying GPU hardware, starting a new model sweep, or retranslating another film merely to test the same settings.
- Treating any publisher QA green light or another complete full-film run as proof of Hulu/Netflix-quality Japanese.

## What remains genuinely worthwhile (ranked)

**A. Highest-value, ZERO NEW INFERENCE: use the existing Benchmark 006 blind pack.** The prior private assistant audit recommended 90 seconds of the same *Hokum* scene, playback 35:00–36:30, using the existing anonymized nine options A–I. That is 9×90sec = ~13.5 minutes, not nine full movies. Once the intended Japanese viewer independently rates comprehension, naturalness, reading comfort and character tone, only two to three finalists need longer evaluation; an untested fourth title remains sealed for confirmation. Do not preview the hidden identity key to the viewer. If the user doesn't want this work, **do not nag them**; select "STOP model-quality R&D" immediately.

**B. Shift the product goal to native/Japanese subtitle ACQUISITION FIRST.** Existing Sublarr/Japanese-first docs show open provider and scan gaps; native OpenSubtitles/SubDL/Jimaku coverage was not established, and score-only title matching is weak. Inspect and configure actual provider availability; acquire exact-title/version full Japanese subtitles where lawfully available, compare cue coverage and synchronize offsets with actual media (verify early/mid/late), protect editorial sidecars. This is a different value proposition with lower risk of machine semantic errors. Sources: [JAPANESE_FIRST_ACQUISITION_AND_SYNC.md](../docs/JAPANESE_FIRST_ACQUISITION_AND_SYNC.md). Do not claim that acquired Japanese subtitles are always human-authored or timing-correct.

**C. For a PARTICULAR wanted film with no sourced Japanese:** use installed E4B as a **machine draft**, clearly labeled and reviewed, or selectively edit a small number of high-impact moments with a stronger assistant/human workflow. Do not market it to the household as 8/10 unattended. Prior successful FROM/Yellowjackets polishing supports editorial review as a different workflow, with unknown time costs and nonidentical models. A free cross-platform editor, [Subtitle Edit 5](https://subtitleedit.github.io/subtitleedit/overview.html), includes waveform synchronization, side-by-side editing, and local translation; it is an editor/workflow option, **not independently proven better translation**.

**D. ONE genuinely new external model exception:** On **November 5, 2026**, Preferred Networks released [PLaMo 3 Translate](https://www.preferred.jp/ja/news/pr20261105) with new 0.8B/2B/8B/31B weights. [Official 2B card](https://huggingface.co/pfnet/plamo-3-translate-2b) documents native PFML3 prompt, previous translated history, style, context, and [official 2B GGUF](https://huggingface.co/pfnet/plamo-3-translate-2b-GGUF); **Q4_K_M 2B is ~1.81 GB**, likely practical for the 6GB GPU. [8B Q4_K_M ~5.28 GB](https://huggingface.co/pfnet/plamo-3-translate-8b) could be tight once KV/memory overhead is included; don't claim fit. The author reports favorable translation benchmark comparisons, **not native Japanese subtitle-quality results**. It has NEVER been tested by Bruiser and is **not** a prompt variant of existing Gemma. **OPTIONAL, AND ONLY AFTER A:** one pre-registered, model-native, small matched unseen-scene trial vs existing E4B; no copying Gemma parameters or prompt, no full movie, no second-pass arbitration, no changes to publisher. If it fails watchability/fidelity or cannot run safely, stop; not an excuse for PLaMo prompt tuning. The PLaMo Community License is not Apache; check distribution and commercial terms before any Bruiser product inclusion. Personal testing is allowed under its stated terms.

**E. Larger multimodal/document-level architecture** could in principle change failure modes (audio/video scene, whole-document meaning), but **it is outside the demonstrated hardware/latency simplicity envelope**. WMT26 [shared-task findings](https://aclanthology.org/2026.wmt-main.58/) associate contextual systems and reviewer selection with stronger performance **for Chinese-source non-Japanese targets**, not proof of EN→JA gain. Do not build this now.

## Stop/go gate — applies to future agents

1. No more new inference or production model edits without an **untried mechanism and a verified evaluation need**. First search this file, RUN_LEDGER and 006 results.
2. An editor-only or native-viewer comparison of existing 006 material is the default next task. Clear target: conversational naturalness/watchability close to ~8/10, no repeated material plot/intent reversal; longer unseen scene confirmation before calling it production-worthy. Blind review is a practical household decision, not a scientific guarantee.
3. If no tested model clears the household's actual enjoyment standard, **STOP development of fully unattended high-quality local EN→JA on this OptiPlex.** Preserve SubHub for acquisition, timing, drafting, checkpoints, export and manual editing. Do not try to recover quality through another parameter, glossary, multistage critic, or model mashup.
4. If the intended user does not want additional evaluation effort, **the present evidence is already enough for a pragmatic STOP** on the 8/10-autonomy objective. Keep the working technology, stop optimization.
5. A new model release may be recorded as a **single** candidate exception, not an ongoing automatic model radar that repeatedly triggers experiments. The Nov 5 PLaMo3 release is concrete; the local-quality benefit is unverified.

**No user media or copyrighted subtitle text is included in this repository document.** Private raw results, source movies, EN/JA paired files and hidden model keys remain private. These restrictions and the current explicit stop/go decision supersede older exploratory model-promotion language for **research**, but do not silently replace the installed operational E4B model.
